# TASK-015：豆包工作只读界面连接排查

日期：2026-11-14。目标：独立验证 Windows 桌面读取能力，不升级客户端、不领取、不改业务代码、数据库或安装包。

## 当前结论

已通过 Windows 自带 UI Automation 读取真实活动页和额度管理页，旧的“界面连接不可用”不再是全部读取渠道的阻塞。此结果替代 TASK-014 中界面通道尚未验证的当前结论，但不代表豆包平台集成已经完成。

## 分层定位及证据

1. Codex 自带 CUA 工具 `cua.getState()` 仍返回 `apps=[]`、`browsers=[]`，错误原文：`Browsers: Error: The browser access host is unavailable`。该错误发生于工具宿主层，未连接到豆包窗口；不能推断豆包进程连接失败、没有活动或没有账号。当前工具未提供宿主内部异常栈、服务状态或修复入口，因此底层为何不可用仍未验证，不编造“未启动某服务”或“权限不足”。该工具的原生桌面入口也未开放，不能用它判断 Windows UIA 能力。
2. PowerShell/.NET 的 UIAutomationClient、UIAutomationTypes 加载成功，RootElement 可访问。探测为交互式会话，探测进程与全部目标进程均在 Session 2；找到目标进程拥有的两个 Chrome_WidgetWin_1 窗口，无访问拒绝异常。排除了本次探测的“完全无法访问桌面/找不到进程/选错进程或会话”。未单独检测全部完整性级别，不能声称所有权限场景已排除。
3. 初始 TreeScope.Descendants 普通控件树只返回 4/14 个外壳节点。改用 TreeWalker.RawViewWalker 后，设置页返回 5/114 个节点；后者有 49 个带名节点、27 个 TextPattern、2 个 ValuePattern。活动页后来返回 803 个 Raw 节点。完整遍历未触及 2000 节点上限。
4. 说明默认视图的单次外壳快照不足以判断客户端可读性；Raw View 路径确实可用。页面切换、Chromium 可访问性延迟初始化也可能影响节点数量，本轮没有控制变量证明仅视图过滤是唯一原因。
5. 用户打开活动页后，按精确 Document 名“免费用豆包工作”读取 TextPattern；只读导航到“设置－订阅与额度管理”，按精确 Document 名“订阅与额度管理 - 豆包”读取真实额度文字。未读取 Cookie、浏览器存储、进程内存或私有业务 API。

## 实际操作与诊断脚本

- 使用标准 UIA 遍历、TextPattern 读取、ScrollIntoView 滚动签到卡片；只对明确识别的“设置”和额度管理导航执行 Invoke，对额度详情执行 Expand。没有点击领取、完成任务、订阅支付或修改设置。
- 独立脚本与脱敏 JSON 存放于 `D:/个人开发软件/AI工作区/outputs/AIClockIn-validation/doubaowork/`，不放入程序包或 data：`probe-uia-readonly.ps1`、`uia-connection-recheck.json`、`uia-quota-read-1.json`、`uia-quota-read-2.json`。
- 复核命令：`powershell -NoProfile -File "D:\个人开发软件\AI工作区\outputs\AIClockIn-validation\doubaowork\probe-uia-readonly.ps1"`。先手动保持官方相关页面打开；脚本本身没有导航、点击、聚焦或领取行为。
- 脚本只保留限定标签和额度数值，不保存整页、聊天、账号名、邀请链接或凭据；业务字段缺失保持 null。读取值不是账号已绑定的签到历史，未写 SQLite。
- 探针开发时发生过 PowerShell 自动变量 `$Matches` 与临时集合重名，以及 Windows PowerShell 5 对无 BOM UTF-8 脚本误读导致正则错误；均已修正并重跑成功。这些是探针错误，不归因于豆包客户端。
