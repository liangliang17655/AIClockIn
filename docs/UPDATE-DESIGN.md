## 2. 方案选择

| 方案 | 优点 | 代价/适用性 |
|---|---|---|
| 增加传统安装程序 | 适合安装目录、快捷方式和卸载管理 | 引入新打包工具、权限与数据迁移问题；当前没有此基础，首期不推荐 |
| **便携版 + 本地独立更新辅助模式（推荐）** | 保持单 EXE 分发；稳定路径；可以只替换程序并回滚 | 需增加有限的更新事务、校验和进程协调代码，必须实际测试故障恢复 |
| 打开浏览器手动下载 | 实现最少 | 不满足自动下载、替换、重启要求，不作为此次方案 |

推荐第二种。辅助程序不是下载来的远程脚本，也不是永久新增服务：将**当前本地已安装 EXE**复制到 D 盘更新临时目录，以 --apply-update 辅助模式独立启动。运行时用户只需一个正式 EXE；辅助副本和下载文件为事务临时产物。

## 3. 用户界面与检查行为

右上角增加“设置”下拉菜单，包含“检查更新”“自动检查更新”勾选项和“关于软件”，保持当前布局。

- 自动检查默认开启；用户切换时只写独立更新偏好文件，不改账号配置或数据库。偏好不随更新覆盖。
- GUI 绘制完成后异步请求；请求超时、限流或离线不阻塞签到与窗口启动。后台任务和独立签到进程不参与检查。
- 手动检查有结果提示：新版本、无需更新、暂无正式发行、网络/限流错误。失败窗口允许重新检查。
- 启动自动检查在版本不高于本地、无正式发行或网络失败时不弹打扰窗口；只有发现可用新版本时展示提示。
- 新版本窗口显示本地版本、远程版本和 Release.body 的纯文本说明；不执行 HTML、脚本或发布说明中的命令。“立即更新”“稍后更新”由用户选择。
- “关于软件”展示版本与固定项目地址。更新说明不硬编码。
- 检查、下载和账号操作分别管理状态；更新检查事件不得误解除进行中签到的 busy 保护。用户已有签到/授权正在执行时，可看说明，实际替换必须等待操作完成或取消本次更新。

## 4. 版本与附件识别

1. 固定请求 https://api.github.com/repos/liangliang17655/AIClockIn/releases/latest，不用 Token。
2. 防御性拒绝 draft=true 或 prerelease=true；只解析 vMAJOR.MINOR.PATCH（允许省略 v），按整数三元组比较，不按字符串比较，不降级。
3. 仅选择明确命名的 Windows x64 程序附件，例如 AIClockIn-v0.2.0-windows-x64.exe；不能挑第一个 .exe，不能接收源码 ZIP。
4. 接受 Release 的 SHA256SUMS.txt；按**该附件完整文件名**匹配唯一的 64 位十六进制 SHA256。重复、冲突或缺少匹配项均拒绝。
5. 若无校验附件，仅在 API 为对应资产提供有效 sha256:... digest 时才允许回退；两者同时存在时必须一致。两种来源都没有则不安装。
6. SHA256 验证传输和发布产物一致性，不等于代码签名或独立的发布者身份认证；信任根仍是固定 GitHub 仓库的发布权限与 HTTPS。本期不引入签名基础设施，也不降低为跳过校验。

GitHub 提供资产下载 URL，下载可能发生重定向；只允许 HTTPS 及明确允许的 GitHub 官方资产域名，初始附件必须来自上述固定仓库/Release，不接受发布说明中的任意链接。[Release assets API](https://docs.github.com/en/rest/releases/assets)

## 5. 下载流程

- 流式下载到 D 盘专用 updates/<事务ID>/，使用 .part 文件；仅完整下载且校验通过后才标记为候选程序。
- 固定超时、有限次数重试及错误提示；失败重试重新下载，不拼接不确定的残片。UI 显示已下载/总字节、百分比和当前阶段；总长度未知时显示字节数及活动状态。
- 校验实际字节长度与 Release 资产 size，并计算 SHA256；检查程序为目标 Windows x64 可执行产物。元数据、发布说明和附件均有大小上限。
- 下载和校验失败不关闭旧软件、不触碰安装 EXE；用户可以重试或稍后更新。
- 校验成功才提示“准备更新并重启”，不执行未验证附件。网络检查与下载不占签到操作锁。

## 6. 替换、重启与失败恢复

### 6.1 更新前

- 固定安装目标只能是当前启动的 AIClockIn.exe，不能由 Release 内容决定路径；保留启动时实际 --data。
- 发现其他同路径 GUI 实例时提示用户先关闭其他窗口，不强杀。已有签到/授权工作应自然完成；等待有超时，超时保留旧版。
- 本地生成更新事务清单，字段仅包括本地目标、候选、备份、预期哈希/版本和重启参数，不包含账号凭据；清单和控制文件不从远程执行。
- 启动独立辅助进程并确认其就绪后才关闭当前 GUI。辅助进程使用独立 PyInstaller 解压生命周期，避免父进程退出时删除它仍需的运行文件。

### 6.2 更新事务

- 用进程句柄等待旧进程及其单文件启动器正常退出，使用限时等待，不以固定 sleep 或强制终止代替。[WaitForSingleObject](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitforsingleobject)
- 用本地更新互斥和现有操作锁协调并发；真正替换期间新的同路径启动/后台调用应限时等待或明确返回忙碌，不读取旧/新混合状态；不注销或改写计划任务。
- 在目标目录准备同卷候选文件，再次核验哈希。创建可恢复的旧 EXE 备份，使用 Windows 文件替换能力执行事务，不直接覆盖正在运行的映像。[ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)
- 替换后运行新版本离线健康检查，确认预期版本、资源、加密与历史模块可加载；健康检查使用合成临时数据，**不能加载、刷新或迁移用户真实账号**。
- 健康检查成功后，释放更新互斥，从原安装路径自动启动 GUI，并传回原 --data。自动重启不带 --silent，不额外触发一次签到。
- 保留一份恢复所需的旧程序和事务状态；下次启动可识别上次中断的事务。不能仅凭“进程启动成功”就宣称新版本完整可用。

### 6.3 失败与异常

- 下载、校验、辅助启动、等待旧实例、权限不足或文件占用失败：尽可能在关闭旧 GUI 前发现；不替换当前程序。
- 替换失败、健康检查失败：从已验证备份恢复程序，给出本地错误信息；不触碰 data。恢复也失败时必须明确报告备份位置，不声称已恢复。
- 应对突然断电/重启的残留事务：启动前识别目标与备份哈希，安全恢复或提示用户处理；不删除无法确认归属的文件。
- 安装目录不可写时不请求隐式提权、不改变安装位置；原版仍保留，提示用户处理权限。
- 外部进程、杀毒软件或硬件损坏可能阻止自动恢复，因此验收必须区分“自动回滚已实测”和“备份可手动恢复”，不能承诺任何外部故障下的绝对成功。

## 7. 数据及计划任务保护

- 更新附件只包含程序，不含 data；不解压远程源码或安装目录整包，不执行删除目录操作。
- 保留当前实际 data/accounts.json、history.db、task-backup.json，自定义 --data 和 DPAPI 用户上下文；不迁移到需求示例的其他结构。
- 不重登、刷新 token、重写账号文件、删除或初始化 SQLite。更新偏好仅在用户切换开关时写独立文件；升级替换本身不重写偏好。
- 旧程序备份、候选、事务报告在 D 盘更新区，下载文件不放 data；操作锁文件属于并发控制，不是账号或数据库迁移。
- AIClockIn-Auto 始终指向原 EXE 名称、目录和 --data；更新器不重装、不移除、不禁用任务。替换完成后核对其定义未变。
- 更新过程中不允许新版本对真实数据做不兼容迁移。以后若有必须迁移的版本，需要另外设计兼容/备份/回滚协议，不能套用本次仅替换 EXE 的规则。

## 8. 发布规范

建议此次新增更新能力的版本为 **v0.2.0**，沿用当前 0.1.0 的版本线；不把示例 v1.0.0 当成已经发布。以 VERSION 为唯一来源，标签、Release、包内版本和附件文件名必须一致。

每个正式 Release：

```text
tag:   v0.2.0
title: AIClockIn v0.2.0
body:  本版本新增、修复、已知问题（用户实际看到的更新说明）
assets:
  AIClockIn-v0.2.0-windows-x64.exe
  SHA256SUMS.txt
```

构建发布脚本在 D 盘输出以上两项并校验包内版本，不打包 data、不用 git pull。可以另保留最新 exe 文件名供人工下载，但自动更新只认规范附件。

操作顺序：本地版本/测试/变更记录一致 → 构建与校验 → 创建 Draft Release → 上传程序与校验 → 核对附件、说明 → 发布为正式版本并标记 Latest。GitHub 自动生成的源码压缩包不属于更新包。

本次准备本地打包/校验工具和发布步骤，不自动提交、打标签、推送或发布 Release。若后续需要 GitHub Actions 自动发布，应单独明确触发/权限和审批，不默认增加远程发布权限。

**引导限制：现有 v0.1.0 没有更新器，不能凭空自动发现 v0.2.0。首次必须手动替换一次带更新功能的 EXE，此后才可应用内更新。** 当前仓库没有正式 Release，完整真实线上升级验收还依赖用户发布测试所需的正式产物。
