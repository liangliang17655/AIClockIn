## 技术证据与缺口

| 环节 | 当前真实能力/证据 | 仍缺条件 |
| --- | --- | --- |
| 登录初始化 | 用户使用官方客户端登录；本机UIA可读取部分可见个人资料 | 无经验证的稳定UID及额度来源绑定；昵称、脱敏手机号和候选豆包号不能直接当稳定身份 |
| 今日是否已签 | UIA此前读到每日签到卡片、+200及累计额；现有代码明确 checkin=状态未知 | 可核验的账号、北京时间日期、明确已签/未签状态；金额不构成日期证据 |
| 执行领取 | AIClockIn没有豆包领取代码，未发送领取请求 | 平台允许方式和可测试的单次提交入口 |
| 到账确认 | UIA真实读取活动赠送总额/已用/剩余与到期时间 | 同账号、当日签到来源的新增奖励记录或其他可靠到账证据；余额可能受消耗/其他活动影响，不能仅凭差值确认 |
| 定时调度 | 现有Windows任务可在当前用户交互会话运行EXE；旧平台保持原流程 | 豆包无人手动开活动页的导航、稳定身份与状态来源及领取方式均未验证 |

agent-checkin 技术思路为客户端调试通道打开同登录上下文的活动页，读取内部活动状态、调用领取或点击页面按钮，再回查。其注释报告了请求缺少页面SDK参数、业务拒绝及状态复核的重要性；是作者环境的第三方记录，不是本机签到证据。不能照搬其内部状态码语义、失败补试策略或调试启动改动。Agent2API/Agent2Providers 的登录会话和内部请求思路同样不能解决平台许可问题，且AGPL代码不能未经许可证评估复制进本项目MIT实现。

## Windows 运行条件

- 当前UIA查询真实通过：官方客户端相关页面已加载、同一Windows用户、交互桌面；本机最小化也曾成功读取额度，不能据此推断最小化可稳定执行签到。
- 锁屏真实结果：输入桌面不可访问，Win32 5，返回失败/未知；不绕过该限制，不误报登录失效。现有路径不支持锁屏领取。
- 客户端完全退出真实结果：客户端未运行，额度为空；没有离线或服务端领取能力。
- 用户未登录Windows、系统睡眠/关机、非交互式任务：不能承诺UIA工作。后台任务并不自动获得已解锁桌面。
- 将来若准入，任务应在相同用户的交互会话下运行；缺条件时记录具体失败，必要时延后到解锁/登录后的获准触发点。不得为重试强制重启客户端、反复提交领取，或把未知标记已签。

## 条件满足后的最小方案（尚未实施/批准具体领取路径）

1. 复用现有模块，分开声明 query/claim 能力；绑定可验证账号，官方登录失效与桌面不可访问分开返回。
2. 先查询当日明确状态；已签仅记录已领取，未知不领取，明确未签才允许一次提交。
3. 在提交前持久化“账号+北京时间日期+活动”尝试记录，避免并发、进程崩溃后重复提交；待确认状态只回查，不再次领取。是否需最小补充存储必须先给迁移评估，不能凭现有 history 表假装已具备原子去重。
4. 使用经平台确认允许的官方接口，或获准的官方客户端界面操作；不提取私人会话、不重建设备签名、不直接照搬第三方私有请求。
5. 回查明确领取状态及实际奖励证据，确认后才写签到成功和实际获得额度；缺证据则结果待确认，earned/余额未知项为空。
6. 手动签到与现有任务调用同一执行模块，保持WorkBuddy/Trae核心不动。任务缺少桌面/客户端条件时如实失败或按批准策略等待下一触发，不改变已发布包假装功能可用。

进入实施至少缺少：平台明确允许的具体渠道；稳定账号与日期状态；可复核到账证据；受控一次真实未签到→领取→复核的测试条件。真实测试还需未领取日期/账号，不能用当天重复领取来验证。当前不要求用户重复升级、登录或查找入口。
